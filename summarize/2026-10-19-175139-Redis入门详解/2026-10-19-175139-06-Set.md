**第06章｜Set：保存不重复的商品标签**

**商品标签首先关心有没有，而不是排第几**

商品 1001 是一把无线机械键盘，运营人员给它添加了“机械”和“无线”两个标签。另一个操作又提交一次“机械”，我们希望标签仍然只有一份。筛选商品时，应用还想快速回答：“这件商品有无线标签吗？”这类不重复成员和成员判断的需求，很适合 Set。

本章使用本地 Redis。安装好 `redis-cli` 并启动 Redis 后，在系统终端执行连接命令，随后把下面的 Redis 命令输入交互窗口。练习中的结果假设相关学习 Key 没有被其他客户端同时修改。

```bash
redis-cli -h 127.0.0.1 -p 6379
```

**Set 是成员集合，没有展示顺序**

可以把 Set 想成一个标签盒：放入已有标签，不会额外多出一份；询问某个标签是否存在，会得到明确的判断。这里的“相同”根据成员的实际内容确定，不会自动理解同义词，也不会统一大小写。

另一个必须先建立的认识是无序。Set 不承诺按插入顺序、字母顺序或热度顺序返回成员。你这一次看到 `mechanical` 在前，下一次输出发生变化，也不能据此认为资料出错。如果页面需要稳定展示顺序，应由应用排序，或选择能够表达顺序的结构。

我们把商品 1001 的标签放在 `learn:redis:product:1001:tags`。其中 `mechanical` 表示机械键盘，`wireless` 表示无线。用这些短标识是为了让练习输出清楚；实际产品还可以维护标签标识与中文显示名称的映射。

**例子一：重复添加，究竟返回什么**

先删除学习 Key，建立空集合的初始条件。`DEL` 返回 `0` 或 `1` 都正常，后面的结果从删除完成后算起。

```text
DEL learn:redis:product:1001:tags
SADD learn:redis:product:1001:tags mechanical wireless mechanical
SADD learn:redis:product:1001:tags wireless
SCARD learn:redis:product:1001:tags
SISMEMBER learn:redis:product:1001:tags wireless
SISMEMBER learn:redis:product:1001:tags portable
SMEMBERS learn:redis:product:1001:tags
```

第一次 `SADD` 返回整数 `2`，因为实际新增两个不同成员，重复的 `mechanical` 没有增加数量。第二次返回 `0`，表示没有新增，并非命令执行失败。`SCARD` 返回成员总数 `2`，不是历史添加次数。

两次 `SISMEMBER` 分别返回 `1` 和 `0`，对应“存在无线标签”和“不存在便携标签”。`SMEMBERS` 返回 `mechanical`、`wireless` 两个成员，顺序没有保证。这些输出应按成员内容比较，而不要把终端的第一个位置写死为某种标签。[SADD 官方说明](https://redis.io/docs/latest/commands/sadd/) 说明了忽略重复成员和新增数量的返回语义。

**例子二：移除标签，不会影响其他成员**

本组紧接上一组，集合起点有 `mechanical`、`wireless` 两个标签。现在移除无线标签，并顺带提交一个原本不存在的标签。

```text
SREM learn:redis:product:1001:tags wireless portable
SCARD learn:redis:product:1001:tags
SISMEMBER learn:redis:product:1001:tags wireless
SMEMBERS learn:redis:product:1001:tags
SREM learn:redis:product:1001:tags wireless
```

第一条 `SREM` 返回 `1`，因为实际只删掉 `wireless`。不存在的 `portable` 被忽略，既不会导致整个操作失败，也不会算成删除成功。此时数量为 `1`，无线成员判断为 `0`，完整集合只剩 `mechanical`。最后再次移除无线标签返回 `0`。

如果继续把最后一个成员也移除，Redis 会删除这个空 Set。对不存在的 Set，`SCARD` 返回 `0`，`SISMEMBER` 返回 `0`，`SMEMBERS` 返回空集合对应的结果。应用通常可以把它们作为没有标签来处理；若业务需要区分“尚未加载”和“确认没有标签”，还得额外设计状态表示。

Set 的天然去重也使重复提交相同成员时容易得到稳定的数据结果。但返回 `0` 的含义仍然要按命令判断：对 `SADD` 是没有新增，对 `SREM` 是没有移除，对 `SISMEMBER` 则是成员不存在。不要把所有整数返回都笼统理解成成功标志。[SREM 官方说明](https://redis.io/docs/latest/commands/srem/) 可以帮助核对移除行为。

**例子三：比较两件商品的共同标签**

商品推荐可能先从简单问题开始：“这两件商品有哪些共同点？”为了独立跟做，本组重新清空商品 1001 的标签，并建立商品 1002 的对照标签。新增的对照 Key 同样属于本章练习数据，末尾会一起清理。

```text
DEL learn:redis:product:1001:tags learn:redis:product:1002:tags
SADD learn:redis:product:1001:tags mechanical wireless
SADD learn:redis:product:1002:tags wireless portable
SINTER learn:redis:product:1001:tags learn:redis:product:1002:tags
SUNION learn:redis:product:1001:tags learn:redis:product:1002:tags
SDIFF learn:redis:product:1001:tags learn:redis:product:1002:tags
SDIFF learn:redis:product:1002:tags learn:redis:product:1001:tags
```

两个 `SADD` 都返回 `2`。交集 `SINTER` 返回共同成员 `wireless`；并集 `SUNION` 返回 `mechanical`、`wireless`、`portable` 三种不同标签，依然不保证输出顺序。这两个命令只返回计算结果，不会把原集合改成结果。

差集 `SDIFF` 以第一个集合为基础，移除后面集合中出现的成员。因此第一种参数顺序返回 `mechanical`，反过来则返回 `portable`。它适合回答“商品甲具有、商品乙没有的标签是什么”，不能把参数交换后仍理解成同一个问题。[SDIFF 官方说明](https://redis.io/docs/latest/commands/sdiff/) 明确指出了这种顺序关系。

这些运算只描述集合关系，不能直接推导两件商品是否适合推荐。标签是否可靠、各标签有多重要，还需要业务规则决定。如果部署的是 Redis Cluster，多 Key 集合运算还要满足相同哈希槽等限制；本章按普通本地实例演示，不据此承诺任意集群 Key 都能直接放在一起计算。

**什么时候适合用 Set，什么时候需要换个思路**

不重复标签、用户已收藏的商品编号、某个活动的参与商品，都有“成员有没有”的特点。Set 能把去重和成员查询放在数据结构层面表达，应用不必先取回完整列表再逐个比较。

但它不会记录收藏时间，也不能按喜爱程度排序。若要展示最近收藏，需要另外保存时间关系；若要排行榜，就需要能关联分数的结构。把这些要求硬塞进成员字符串，后续查询通常会变得别扭。

标签值也要统一格式。`wireless`、`Wireless` 与末尾多一个空格的 `wireless ` 是不同成员。应该在写入前确定标准标识，而不是期待 Redis 依据中文含义或大小写自动去重。修改数据库中的标签关系，也不会自动修改这里的集合；两份数据的维护流程仍属于应用职责。

集合规模同样影响使用方式。只判断无线标签是否存在时，使用 `SISMEMBER` 就能表达目的，没必要先 `SMEMBERS` 取回所有标签。对于很大的集合，完整返回和集合运算会涉及更多数据；“使用内存数据库”不等于任何大小的结果都适合一次取完。

最后要区分两个查询方向。本章按商品编号组织标签，适合回答“商品 1001 有哪些标签”。如果页面想查“所有带无线标签的商品”，这个 Key 的组织方式并不能自动给出全部答案。数据存在哪里，往往取决于最常执行的问题；不能因为使用了集合，就认为任何方向的关系查询都会同时建立好。先写清楚查询目标，再选择成员和 Key 的含义，能避免后续不断遍历大量商品来拼结果。

**做一个练习，并删除学习数据**

在第三组结束后，给商品 1001 添加 `portable`。先预测新增数、成员总数和两件商品的交集，再用命令验证。预期新增 `1` 个，总数变为 `3`，交集包含 `wireless` 和 `portable`，顺序任意。重复执行同一次添加，新增数应为 `0`。

结束后只删除本章两个学习 Key。若它们都仍存在，`DEL` 返回 `2`；实际返回取决于练习中是否提前删过。两次 `SCARD` 随后都应返回 `0`。

```text
DEL learn:redis:product:1001:tags learn:redis:product:1002:tags
SCARD learn:redis:product:1001:tags
SCARD learn:redis:product:1002:tags
```
