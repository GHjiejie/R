**第04章｜Hash：分别保存商品字段**

**商品资料为什么有时需要拆成字段**

商品详情页需要整份资料，而商品列表可能只显示名称和价格。运营人员调整价格时，也可能只想修改价格字段。若把所有内容都放在一段 JSON 中，每次局部访问都得读取和解析整个值。Hash 提供了另一种组织方式：把一件商品作为一个 Key，把商品属性保存成其中的字段和值。

本章假设本地 Redis 已启动，且你已安装 `redis-cli`。先在系统终端连接，再执行示例中的 Redis 命令。所有例子只操作商品 1002 的学习 Key，并假设没有其他客户端同时更改它。

```bash
redis-cli -h 127.0.0.1 -p 6379
```

**认识外层 Key 和内层字段**

`learn:redis:product:1002:fields` 是商品资料卡的名字。卡片里面可以有 `name`、`price_cents`、`stock` 等字段，每个字段对应自己的值。字段名只在这个 Hash 内有意义；另一件商品也能使用 `name`，不会因此覆盖本商品。

可以把它想成一张带编号的表单，但不要把它当作关系数据库的一张表。Redis 不会自动规定哪些字段必填，不会替你检查价格范围，也不会建立外键关系。字段的命名、含义、转换和校验，仍由应用负责。

普通字段值可以先按字符串理解。保存 `29900` 后，读取到的是表示数字的内容，应用根据需要转换成整数。把 `price_cents` 定义为以分为单位，能让写入方和读取方遵守同一约定；只写一个含糊的 `price`，反而容易混淆元与分。

**例子一：建立一张商品资料卡**

先删除本章学习 Key。`DEL` 的返回值依赖原来是否存在，可以是 `0` 或 `1`；删除完成后，下面的新增字段数就有明确的初始条件。

```text
DEL learn:redis:product:1002:fields
HSET learn:redis:product:1002:fields name keyboard price_cents 29900 stock 20
HGET learn:redis:product:1002:fields name
HGET learn:redis:product:1002:fields price_cents
HLEN learn:redis:product:1002:fields
TYPE learn:redis:product:1002:fields
```

`HSET` 返回整数 `3`，因为这次新建了三个字段。两次 `HGET` 分别读到 `keyboard` 和 `29900`。`HLEN` 返回 `3`，计算的是字段数量；`TYPE` 返回 `hash`，说明外层 Key 保存的是一个 Hash。

这里一条 `HSET` 可以写入多组字段和值。参数必须成对出现，每个字段后面都有对应的值。若商品名称含空格，例如 `mechanical keyboard`，应使用引号把它作为一个参数输入，避免被命令行拆成额外字段。

**例子二：更新价格，并只取需要的字段**

本组紧接上一组执行，起点是已有三个字段、价格为 `29900`。更新价格后，一次读取名称、价格和一个尚不存在的字段。

```text
HSET learn:redis:product:1002:fields price_cents 27900
HGET learn:redis:product:1002:fields price_cents
HMGET learn:redis:product:1002:fields name price_cents color
HGETALL learn:redis:product:1002:fields
HLEN learn:redis:product:1002:fields
```

这次 `HSET` 返回 `0`，但更新已经完成。这个数字表示新增字段数，并不表示成功与失败；修改已有字段不会让字段数量增加。随后 `HGET` 读到 `27900`，`HLEN` 仍是 `3`。[HSET 官方说明](https://redis.io/docs/latest/commands/hset/) 对返回值作出了这一约定。

`HMGET` 按你请求字段的顺序返回值，因此结果依次对应 `keyboard`、`27900` 和空结果。第三项为空，只说明没有 `color` 字段，不代表其他字段也不存在。即使整个 Hash 不存在，`HMGET` 也会按所请求字段的数量返回一组空结果。

`HGETALL` 返回全部字段和值。默认交互界面通常把字段名与字段值交替展示，客户端库则可能转换成对象或字典。不要依赖这些字段的输出顺序来绑定业务含义；应当按字段名识别资料。只需要两个字段时，`HMGET` 往往比反复读取全部内容更合适。[HMGET 官方说明](https://redis.io/docs/latest/commands/hmget/) 说明了顺序和缺失值的语义。

**例子三：删除一个字段，与删除整件商品缓存**

继续使用上一组的结果：资料卡有名称、价格和库存三个字段。假设页面不再展示库存，需要从这份资料中移除 `stock`，同时观察一个不存在字段的读取结果。

```text
HDEL learn:redis:product:1002:fields stock
HGET learn:redis:product:1002:fields stock
HEXISTS learn:redis:product:1002:fields stock
HLEN learn:redis:product:1002:fields
EXISTS learn:redis:product:1002:fields
HGET learn:redis:product:1002:fields name
```

`HDEL` 返回 `1`，表示实际移除了一个字段。随后库存读取为空，`HEXISTS` 返回 `0`，字段数变为 `2`。外层 Key 仍存在，所以 `EXISTS` 返回 `1`，名称也仍能读到 `keyboard`。这就区分了“字段不存在”和“整张资料卡不存在”。

`HDEL` 处理 Hash 里面的字段，而 `DEL` 删除整个 Key，包括其中全部字段。如果最后一个字段被删除，Redis 也会移除这个空 Hash；因此应用不应依赖一个没有字段的 Hash 长期占住 Key。[HDEL 官方说明](https://redis.io/docs/latest/commands/hdel/) 可以用于核对这一行为。

**Hash 带来的便利，以及它没有承诺的事情**

字段更新可以减少应用为了修改一个属性而重新拼装整份对象的工作。用户资料、设备状态、商品的少量平面属性，都可以按这种方式组织。它尤其适合字段有明确含义、经常需要分别访问的对象。

如果字段里又塞入一大段复杂嵌套 JSON，那么这个字段内部仍然需要应用自己解析和重写。Hash 不会因为字段名叫 `specifications`，就自动理解里面的规格层级。大量商品也不宜全部塞进同一个 Hash，形成一个无限增长、归属含糊的巨型对象。

还有一个常见误解：执行 `HSET price_cents 27900`，改变的是 Redis 中这个字段。它不会自动调用业务数据库，更不会通知支付或订单系统修改价格。数据库更新与缓存同步属于应用流程；本章的命令练习只是观察 Redis 数据如何变化。

单条 `HSET` 可以同时写多个字段，但应用如果分多次发送不同命令，中间仍可能穿插其他客户端的操作。不能因为数据放在一张“资料卡”里，就认为一连串读取和修改天然构成完整业务事务。先分清单条操作的范围，后续学习并发控制时才不会混淆。

另一处容易与整份 JSON 混淆的地方，是没有提交的字段如何处理。执行 `HSET` 只更新本次指定的字段，原有但未提到的字段会继续保留。假如新版本商品资料不再包含某个旧属性，只把新字段逐项写进去，并不会自动清除旧属性；应用需要明确决定何时使用 `HDEL`，或怎样重新生成整份缓存。这是按字段更新带来的实际行为，应该在数据结构设计时就想清楚。

同样，字段可以保存空字符串，它与不存在的字段不同。只用“读到的内容是不是空文本”判断字段是否存在，会把两种情况混在一起；需要区分时，可以使用 `HEXISTS`，或依据客户端返回的缺失标记判断。对于必填的名称和价格，应用应逐项校验，而不是只看到外层 Key 存在就认为商品资料完整。

**把易错点变成一个短练习**

在上面的两个字段仍存在时，执行下面的命令，先预测返回数字，再验证名称是否保留、价格是否更新、颜色是否新增。

```text
HSET learn:redis:product:1002:fields price_cents 25900 color black
HMGET learn:redis:product:1002:fields name price_cents color
HLEN learn:redis:product:1002:fields
```

预期 `HSET` 返回 `1`，因为只新增了 `color`；价格虽然更新，也不计入新增数。读取结果依次为 `keyboard`、`25900`、`black`，字段总数变回 `3`。如果你得到不同结果，先确认上一组是否完整执行，尤其是 `stock` 是否已经删除。

练习结束，删除整张学习资料卡，再确认读取为空。这里不会操作真实数据库，也没有修改其他商品。

```text
DEL learn:redis:product:1002:fields
HGET learn:redis:product:1002:fields name
```
